# かな소리

기존 가나 학습 자료에서 소리와 글자를 연습하고, 브라우저 음성 인식으로 얻은 문자의 일치율을 저장합니다. **음성 파일은 생성·전송·저장하지 않습니다.** 교사는 아이디와 비밀번호로 로그인해 담당 학급의 결과를 조회하고 평가 결과와 학생별 요약을 CSV로 내려받습니다.

## 실행

Node.js 24 이상이 필요합니다. 최초 실행 전 `npm ci`로 로컬 히라가나 변환 사전(kuromoji)을 설치하세요. 사전 변환을 위해 외부 서비스로 인식문을 전송하지 않습니다.

```powershell
npm start
```

학생 시작: http://127.0.0.1:5500/ · 교사: http://127.0.0.1:5500/teacher.html

기존 `python -m http.server` 같은 정적 서버만으로는 로그인과 결과 저장을 사용할 수 없습니다. 서버는 기본적으로 로컬 인터페이스에만 바인딩됩니다.

## 학급과 교사 설정

기본 계정과 공용 기본 비밀번호는 없습니다. 다음 명령으로 운영자가 계정을 만들고 담당 학급을 지정합니다. 교사 비밀번호인 `SETUP_SECRET`은 12자 이상으로 설정하세요. 교사 비밀번호는 scrypt 해시로 저장됩니다. 학생은 학번과 이름만 입력합니다.

```powershell
# 아래 값은 예시입니다. 실제 비밀값으로 교체하세요.
node server/admin.mjs class class-301 "3학년 1반"
$env:SETUP_SECRET = '여기에-교사-비밀번호'
node server/admin.mjs teacher teacher-kim "김 선생님" class-301
Remove-Item Env:SETUP_SECRET
```

같은 명령을 다시 실행하면 학급 이름/교사 비밀번호를 변경할 수 있습니다. 교사 명령의 마지막 학급 목록이 해당 교사의 전체 권한을 대체하며 기존 교사 세션은 만료됩니다. 학급을 생략하면 모든 학급 조회 권한이 제거됩니다. 여러 교사에게 같은 학급 권한을 부여할 수 있습니다.

학생은 교사가 사전에 등록한 학번과 이름이 정확히 일치하고 수집·이용에 동의해야 입장할 수 있습니다. 불일치하거나 여러 학급의 명단과 중복 일치하면 입장이 차단됩니다. 기본적으로 명단에서 학급을 찾으며, 특정 학급으로 제한하려면 STUDENT_CLASS_ID를 지정하세요. 학번과 이름은 비밀 인증 수단이 아니므로 타인의 정보를 아는 사람의 대리 입장까지 막지는 않습니다. 세션은 8시간 후 만료됩니다.

## 교사 인증과 출석부

시작 화면의 ‘교사 입장하기’는 기존 교사 세션을 확인해 로그인 중이면 출석부로 바로 이동합니다. 로그아웃했거나 세션이 만료된 경우 인증창이 열립니다. 비밀번호로 인증하면 출석부로 이동합니다. 비밀번호만으로 교사를 구분하므로 교사별로 서로 다른 비밀번호를 설정하세요. 기존 학습 결과 화면은 출석부 상단의 ‘학습 결과’에서 열 수 있습니다.

- 출석부에서 담당 학년·반을 선택하고 ‘학생 명단 등록’을 펼쳐 학번과 이름을 한 줄에 한 명씩 붙여 넣으세요. 엑셀의 두 열을 복사해 붙여 넣을 수 있습니다. 명단은 선택한 학급에 추가되고 기존 명단은 유지됩니다. 등록된 학번의 이름이 다르면 전체 등록을 취소하며 운영 담당자의 확인이 필요합니다.
- 학년·반 표시는 관리자 명령에서 지정한 학급 이름을 사용합니다. 예: 3학년 1반. 인원은 등록된 명단으로 집계하므로 아직 로그인하지 않은 학생도 결석 인원에 포함됩니다.
- 출결은 한국 시간 기준 날짜별로 저장됩니다. 오늘 로그인한 학생은 출석으로 기록되고 교사 화면은 5초마다 갱신됩니다. 날짜가 바뀌면 새 날짜의 미출석 상태로 표시됩니다.
- 결석 목록의 ‘출석’ 버튼은 해당 학생을 출석으로 변경합니다. 수동 입력에서 학번·이름·출결 상황을 입력해 반영하면 통계와 목록이 갱신되고 입력란은 초기화됩니다. 학생이 재입장하면 다시 출석으로 기록됩니다. 브라우저를 닫는 것만으로 결석 처리되지는 않습니다.
- 새 미리보기는 3학년 1~10반의 빈 명단을 제공합니다. 교사 비밀번호는 local-demo-password입니다. 명단을 등록한 후 학생 입장이 가능하며, 미리보기 데이터는 재시작 시 초기화됩니다.


## 저장·판정·다운로드

교사 화면은 예시의 성장 분석 흐름에 맞춰 반 선택, 요약 지표, 반별 평균·첫 시도/최근 시도·점수 분포 그래프, 먼저 살펴볼 학생, 정렬 가능한 학생별 성장 표, 항목별 평균 순으로 구성됩니다. 학생 이름이나 성장 그래프를 누르면 개별 연습 기록과 CSV 다운로드가 열립니다. 전체 평가 CSV와 학생별 요약 CSV도 지원합니다.

교사 인증 후 출석부에서 학습 결과를 열면 기존 교사 세션을 확인해 결과를 바로 표시합니다. 로그인하지 않았거나 세션이 만료된 경우에만 로그인 화면을 표시합니다. 교사와 학생은 서로 다른 세션 쿠키를 사용하므로 교사 로그인·로그아웃이 학생 기록을 바꾸지 않습니다. 메인 화면의 ‘기록 보기’는 입력한 학번·이름의 현재 학생 세션으로 들어갑니다. 입력 정보가 현재 학생과 같으면 기존 세션의 연습 기록이 유지되고, 다른 학생이면 별도 세션으로 시작합니다. 학생 세션은 다른 학생의 이전 참여 기록이나 교사의 전체 학급 결과를 조회할 수 없습니다.

평균 점수는 학생별 평균을 다시 평균한 값입니다. 평균 성장은 2회 이상 점수가 있는 학생만 포함하며, 첫 평가와 최근 평가의 차이입니다. 서로 다른 연습 항목이 포함될 수 있어 정밀한 능력 변화 지표로 해석하지 않습니다. 점수가 없는 기록은 평균과 분포에서 제외합니다. 먼저 볼 학생은 미통과, 10점 이상 하락, 1회만 연습 등의 명시적인 기록 기준으로 표시합니다.

`npm run preview`로 3학년 10개 반의 로컬 체험 화면을 실행할 수 있습니다. 주소는 `http://127.0.0.1:5512/teacher.html`, 계정은 `demo` / `local-demo-password`입니다. 미리보기는 메모리 DB만 사용하며 재시작하면 빈 명단으로 돌아옵니다. 운영 DB와는 분리됩니다.

- 저장 위치: `data/kanasori.sqlite`. `DATA_DIR`로 다른 영구 저장 디렉터리를 지정할 수 있습니다. 서버와 관리자 명령은 같은 `DATA_DIR`을 사용해야 합니다.
- 저장 항목: 등록 학생 명단, 날짜별 출결 상태와 변경 시각, 학급, 학번, 이름, 연습 항목, 목표 글자, 인식된 말, 점수, 통과 여부, 서버 기록 시각, 세션 소유자 식별자 및 중복 방지 ID.
- 점수는 서버가 공통 `assess` 함수로 다시 계산하며 통과 기준은 70%입니다. 학생이 보낸 점수·학번·학급은 신뢰하지 않습니다. 대상 행은 서버의 가나 목록에서 결정됩니다.
- 브라우저가 인식한 문자에 대한 연습용 평가입니다. 녹음 음원의 음향 분석이나 억양·장단음의 정밀 발음 평가가 아닙니다. 브라우저 음성 인식에서 음성이 제공업체 서버로 전송될 수 있습니다.
- 연습 도중 행 변경을 막고 저장 성공을 확인한 뒤 다음 연습을 허용합니다. 실패 시 같은 ID로 재시도해 중복 저장을 방지합니다. 페이지를 닫기 전 미저장 결과를 안내합니다.
- 교사 화면에서 학급/학번을 선택하거나 학생 이름을 눌러 결과를 필터링합니다. CSV에도 같은 필터와 서버 권한 검사가 적용됩니다. CSV는 UTF-8 BOM 및 수식 주입 방지 처리를 포함합니다.
- 결과는 먼저 `/api/attempts`로 영구 DB에 저장합니다. 구글 시트 연동 설정 후에는 서버가 30초마다 미전송 기록을 보내며 기록 ID로 중복을 방지합니다. 미리보기에서는 전송하지 않습니다.

## 운영 배포

단일 Node 프로세스와 영구 디스크가 있는 서버에 배포하는 구성입니다. Vercel 정적 배포나 일시적인 서버리스 파일시스템에 SQLite를 올리는 구성은 지원하지 않습니다. 해당 환경에서는 별도 영구 DB 연결이 필요합니다.

리버스 프록시에서 HTTPS를 설정하고 아래 환경변수를 지정합니다.

```text
NODE_ENV=production
APP_ORIGIN=https://실제-서비스-도메인
HOST=0.0.0.0
PORT=5500
STUDENT_CLASS_ID=class-301
DATA_DIR=/영구저장경로/kanasori
```

`APP_ORIGIN`은 끝에 `/` 없이 실제 접속 origin과 같아야 합니다. 운영 모드는 HTTPS origin이 없으면 시작하지 않으며 세션 쿠키에 Secure를 설정합니다. 브라우저의 마이크는 HTTPS 또는 localhost에서 사용하세요. 음성 인식과 Ruffle 학습 자료에는 인터넷 연결이 필요합니다.

운영 전 학교에서 결과 보관 기간과 문의처를 결정하고 시작 화면 개인정보 안내를 갱신하세요. 현재 자동 파기 작업은 없으므로 운영자가 정한 보관 기간에 따라 삭제·백업을 관리해야 합니다. SQLite 백업은 서버를 멈춘 후 데이터 디렉터리 전체를 복사하거나 SQLite의 온라인 백업 기능을 사용하세요. 실제 교사 계정 설정과 외부 서비스 배포는 아직 수행하지 않았습니다.

## 발음 인식과 음량 보정

- 통과 기준은 모든 단어에서 70% 이상입니다. 브라우저가 반환한 첫 번째 인식 문자를 평가하며 정답에 가까운 다른 후보를 골라 점수를 높이지 않습니다.
- 짧은 단어도 연속 인식과 중간 결과 수신을 사용합니다. 확정 결과가 오면 중간 결과를 대체하고, 종료 시 확정되지 않은 인식 문자가 남아 있으면 마지막 중간 문자를 사용합니다. 아무 문자도 인식하지 못한 경우에는 점수를 만들어 저장하지 않습니다.
- 녹음 버튼을 누르고 ‘듣고 있어요’가 표시된 뒤 발음하세요. 발화 종료 후 2.5초를 기다려 결과를 받으며, 버튼을 다시 눌러 직접 종료할 수도 있습니다. 인식 중 별도의 마이크 스트림을 열지 않습니다.
- 자동 검사는 10개 행과 46개 단어의 인식 이벤트·재시도·결과 저장 및 70% 경계 동작을 검증합니다. 실제 헤드셋과 브라우저 음성 인식 서비스의 정확도는 기기에서 확인해야 합니다.
- 현재 학습에 사용되는 20개 SWF와 101개 안내 WAV의 음성 229개를 활성 구간 RMS 약 -23.735 dBFS로 보정했습니다. 음성 피크는 -3 dBFS 이하이며 짧은 효과음은 증폭하지 않습니다. 음높이·속도·이벤트 음원의 샘플 수를 유지합니다.
- 보정 전 파일은 data/content-audio-originals, 측정 기록은 data/content-audio-normalization.json에 보관합니다. 재처리는 tests/normalize-content-audio.py에 --ffmpeg 경로 및 --apply를 전달합니다.

## 일본어 교과서체

사용자가 제공한 NTk2kp / NTk3kp / NTk4kp TTC에서 W2·W3·W4 웹폰트를 생성했습니다. 일본어 웹 텍스트는 css/japanese-fonts.css를 사용하고, 활성 학습 SWF 20개의 가나 글리프 208개에도 W3를 적용했습니다. 글자 코드·선택 위치·음원·획순 애니메이션 태그는 유지합니다. 원본 콘텐츠는 data/font-originals에 보관합니다. 음원 보정을 다시 실행할 때는 tests/apply-kyotai-fonts.py를 마지막에 실행해 글꼴 적용을 유지하세요.

단어를 변경하면 진행 중인 인식을 취소하고 이전 결과가 새 단어에 덮어쓰이지 않게 합니다. 인식 중 한자는 표시하지 않고 히라가나 변환 완료 후 표시합니다. おおい는 ‘오-이’로 발음하도록 안내하되 목표와 장음 인식 결과 표기는 おおい로 유지합니다.

아·카·사행의 획순 영상 15개(741프레임)는 tests/clean-stroke-videos.py로 압축 잡음과 작은 고립 점을 정리했습니다. 프레임 수·크기·순서와 음원·글꼴·그리기 도구는 유지하며, 원본은 data/stroke-cleanup-originals에 보관합니다. 글자 탭에도 KanaKyotai 교과서체를 직접 지정합니다.

시트에 연결한 `gas/Code.gs`의 setup 함수를 실행하고 구글 권한을 승인합니다. 스크립트 속성 SYNC_TOKEN을 서버 환경변수 SHEETS_SYNC_TOKEN으로 지정합니다. 웹앱을 소유자 권한으로 배포하고 발급된 /exec URL을 SHEETS_WEB_APP_URL로 지정합니다. 토큰은 브라우저 코드나 공개 저장소에 넣지 않습니다. 이후 운영 서버를 재시작하면 미전송된 기존 기록부터 전송됩니다. 시트를 바꾸려면 기존 전송 확인 기록에 대한 별도 이전 계획이 필요합니다.

현재 상태: 시트와 코드 준비 완료, Google 실행 권한·웹앱 배포·서버 환경변수 설정은 대기 중입니다. 실행 중인 5512 미리보기는 메모리 기록 보존을 위해 자동 재시작하지 않았습니다. 운영 DB에는 학급만 준비했으며 교사 계정과 실제 명단은 아직 없습니다.
